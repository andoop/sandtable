# REDTEAM 轮 2 · README 首页重塑（实现级对抗）

## 结论
`BREACH_FOUND`

本轮对当前 `README.md` 成稿发起 3 个红军 OPFOR 子 agent，从首屏优先级、`superpowers` 对比红线、以及试用链路三个方向攻击实现。3 个方向均给出了可复现杀招，且主 agent 已核实成立，因此本轮不计入任何“稳住了”的实现信心。

## 已核实破口

1. **正式对比区块前置过深**
   - 表现：`README.md` 在首屏微对比之后、很快就展开完整 `Sandtable vs Superpowers` 对比区块。
   - 后果：打破“前两屏只留 1 条极短微对比，完整对比应下沉后文”的硬约束，挤占“为什么值得试 / 如何闭环防失控”这两个前两屏判断题。
   - 证据：`README.md:24`、`README.md:34-37`；对应 `prd.md:37`、`prd.md:73`、`tests.md:58-64`。

2. **首屏记忆点退化成名词墙**
   - 表现：首条记忆点把 `MENTAL_REHEARSAL`、`REDTEAM`、`IMPL_REHEARSAL` 三个方法论名词并列塞进同一 bullet。
   - 后果：打破“每条记忆点只允许 1 个能力 + 1 个结果，不得并列多个方法论名词”的可扫描性要求。
   - 证据：`README.md:5`；对应 `prd.md:76-78`、`tests.md:51-55`。

3. **正式对比区块的一句多锚点/多解释**
   - 表现：`README.md:35-37` 的第二句不止一个具体名词锚点，还夹带解释性结论。
   - 后果：打破 `TC3` 与 `FR3` 对“每句一个具体名词锚点、不得一句并列多个锚点”的硬约束。
   - 证据：`README.md:35-37`；对应 `prd.md:37`、`prd.md:61-64`、`tests.md:23-27`。

4. **首屏试用摘要不是可行动摘要**
   - 表现：首屏“立刻试用”只承诺跳到 `Quickstart` 后可拿到第一条命令，没有把最短下一步直接写在首屏。
   - 后果：打破“首屏就知道先执行哪一步”“不得只留弱锚点”的硬要求。
   - 证据：`README.md:11` 与 `README.md:52-55`；对应 `prd.md:40`、`prd.md:89`、`tests.md:44-48`。

## 主 agent 裁决
- 以上 4 处均已亲自核实成立，属于实现级 breach，而非红军误报。
- 当前 `README.md` 尚不能通过这轮红队验收。
- 下一步可选：`(a)` 直接修 README 后再打一轮实现级 redteam；`(b)` 先保留战报，等待开发者裁决再修。
