# README GitHub 首页重塑 · 测试用例

> 我在用 writing-tests 把需求具体化为测试用例。
> 黑盒、场景化、人可读。每条用例必须映射回 `prd.md` 的 FR / 验收标准 / MUST / MUST NOT。
> 审阅指引：开发者先读本文件判断“这个 README 首页是不是已经把价值讲清楚了”，再读 PRD §6 勾选是否做完。

---

## TC1 · 首屏让新访客快速看懂 Sandtable 是什么
- **映射**：FR1 / 验收“前两屏内讲清一句话价值”
- **Given**：一个第一次进入仓库、此前不知道 Sandtable 的开发者。
- **When**：他只阅读 README 开头与首页前两屏内容。
- **Then**：他能直接看到一句清晰价值主张，知道 Sandtable 是给 coding agent 用的方法论插件，知道它不是“让 AI 直接开始写代码”，而是“先侦察、定目标、写计划、做推演、发现异常再回修正”的开发闭环；同时他也能看懂这套方法是在避免什么失控或返工，并换来什么结果。
- **状态**：待验证

## TC2 · 流程图让人一眼看出闭环与回退机制
- **映射**：FR2 / MUST“必须有清晰流程图”
- **Given**：访客浏览 README 的“工作方式/流程”部分。
- **When**：他看到流程图。
- **Then**：图中能明确看到从需求进入，到 `RECON / OBJECTIVES / TESTCASES / PLAN / MENTAL / REDTEAM / IMPL / VERIFY` 的主路径，并能看懂“发现 anomaly/breach/block 就回到修正循环”，而不是线性流水线；并且该图出现在首个滚屏内或紧接首屏下方，而不是埋在更后面的 section。即使访客不懂这些术语，他也能从图内或紧邻的白话说明中看懂“先摸清、再定目标、再计划、再预演、出问题就回修正”。
- **状态**：待验证

## TC3 · 对 superpowers 的对比必须逐点两句制，且只允许事实差异
- **映射**：FR3 / MUST“必须有 superpowers 对比” / MUST NOT“不得虚构对方没有的能力”
- **Given**：一个已经知道 `superpowers` 的开发者。
- **When**：他阅读 README 里的对比区块。
- **Then**：对比区块中的每一个 bullet 或对比点都必须严格只有两句：第一句是一个可回指到已核读 `superpowers` README 的事实锚点；第二句是一个可回指到 Sandtable 仓库内事实的对应差异。两句都必须各自显式包含一个具体名词锚点，不接受宽泛总括句。它不会把 `superpowers` 说成缺少规划、子 agent、worktree 或开发方法论，也不会出现任何没有事实锚点的优越性判断、“更像/更能/更值得试”之类软性 superiority framing、脱离仓库事实的体验推断、第三句点评句或形容词结论句。
- **状态**：待验证

## TC4 · README 前置了 Sandtable 的记忆点，而不是把优势埋在后文
- **映射**：FR4 / 验收“核心流程和差异化优势前置”
- **Given**：访客快速扫描 README 的标题与前几个 section。
- **When**：他尚未阅读安装细节和完整命令表。
- **Then**：他已经能感知 Sandtable 的几个核心记忆点：三类推演、异常即停并回修正、`docs/sandtable/` 持久状态与记忆、`/sandtable-autopilot`、以及“这套方法论在本仓自举使用”。如果他已经知道 `superpowers`，前两屏内还能看到 1 条极短、基于已核实事实的微对比信号，足以知道 Sandtable 不是同题复述。
- **状态**：待验证

## TC5 · 自举迭代的证据是明确可见的
- **映射**：FR5 / 验收“明确传达自举信号”
- **Given**：访客对“你们自己真的用这套方法吗”持怀疑态度。
- **When**：他阅读 README 中关于仓库实践的部分。
- **Then**：他能看到这是一个正在用 Sandtable 自己迭代自己的仓库，而不是单纯宣讲；README 至少会提及 `docs/sandtable/`、feature 记录或自举式改进这一事实。
- **状态**：待验证

## TC6 · 首页改造后仍然能沿唯一默认路径直接试用
- **映射**：FR6 / 验收“仍保留安装与命令入口”
- **Given**：一个被首页说服、准备立刻试用的开发者。
- **When**：他从 README 顶部开始顺序往下阅读，不跳到其它文件。
- **Then**：他在首屏就能看到一条可行动的“立刻试用”摘要，知道默认推荐路径是什么、去哪里安装/接入以及先执行哪一步；前两屏内还能看到一个可单跳到同一 `Quickstart` 区块的锚点；该区块内允许有两个极短子块，分别服务 Claude Code 与 Cursor，但两个子块都必须在同一落点内按固定顺序同时给出 1 条安装命令/动作、1 个接入动作、以及安装后的第 1 条命令入口，不需要翻其它 section 才知道怎么开始。对于 Cursor，默认推荐路径只能有一个首选，不能再把“让 AI 读 `INSTALL.md`”和“手工拷 `.cursor/`”并列成双选题。若 README 保留 Cursor 本地插件路径，则 caveat 必须紧跟路径标题或第一条动作之前出现。
- **状态**：待验证

## TC7 · AI 与人都容易扫描和引用
- **映射**：FR7 / MUST“AI 友好”
- **Given**：一个人类访客和一个需要读取 README 的 AI agent。
- **When**：它们读取 README。
- **Then**：README 的层级、标题、段落和列表都是稳定可扫描的，没有大段重复宣传文，没有难以提炼的冗长首屏；新增首页模块伴随压缩或合并旧内容，而不是简单叠加；首屏记忆点不会变成名词墙，每条都只表达一个能力和一个结果，其中至少两条是结果导向句，并且每条结果都能回指到 README 内紧邻可见的流程、目录、命令或仓库事实；标题下副文、首屏主句和 `Why` 段也都不出现无锚点口号句；关键概念能被直接引用。
- **状态**：待验证

## TC8 · 首页形象增强不能以入口后移和篇幅膨胀为代价
- **映射**：FR6 / FR7 / MUST“立刻试用入口前置” / MUST“控制首页篇幅”
- **Given**：一版已经完成重塑的 README。
- **When**：开发者人工检查首页阅读顺序与信息密度。
- **Then**：首屏只包含标题、1 句副文、`<=5` 条记忆点和 1 条试用入口摘要；前两屏内优先服务“为什么值得试”和“它如何闭环防失控”这两个判断题；前两屏内能看见“怎么立刻试”的入口锚点，也能看见 1 条极短、事实型的 `superpowers` 微对比信号，但不会展开完整对比表或完整 Quickstart；`superpowers` 对比、自举证明与完整 Quickstart 展开下沉到更后面的 section；README 不是在旧内容之上纯叠加，而是明显做了删改、合并和重组，且总行数不超过 160 行。
- **Then（顺读式验收）**：从标题开始，只允许顺读和一次锚点跳转，审阅者必须在 README 内拿到一条可复制的安装命令、一个明确接入动作、以及安装后的第一条命令；否则判失败。
- **Then（顺读式验收）**：从标题开始，只允许顺读和一次锚点跳转，审阅者必须在 README 内同一个 `Quickstart` 落点拿到一条可复制的安装命令、一个明确接入动作、以及安装后的第一条命令；否则判失败。
- **Then（文案红线验收）**：若出现无锚点优越词、替读者下判断句、抽象口号句、或两句制对比之外的点评句中的任意一种，即整版 README 文案验收失败。
- **状态**：待验证
