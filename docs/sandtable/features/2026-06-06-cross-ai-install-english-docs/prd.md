# Prompt-Language Localized Install Assets · PRD

> 对应 `project.md` 北极星 / 继承 `constraints.md` 红线。实现细节见 `plan.md`。

## 1. 目标
让用户把哪种语言的官方安装提示词复制给 AI，AI 就按那种语言把 Sandtable 安装进当前项目；首期支持中文与英文两种本地资产语言，并保持现有“不覆盖已有文件、按 harness 接线”的安装红线。

## 2. 背景与现状
- 当前 `README.md` 与 `INSTALL.md` 都只有中文官方安装提示词：“阅读 ... `INSTALL.md` 并据此把 Sandtable 安装进当前项目。”；仓库没有并列的英文官方提示词，也没有说明 AI 应如何根据用户贴过去的话选择安装语言（`README.md`、`INSTALL.md`）。
- 当前安装路径会把仓库内同一套自然语言资产复制到用户项目，包括 `AGENTS.md`、`skills/`、`commands/`、`.cursor/commands/`、`templates/` 等；这些资产目前主要是中文，因此英文提示词即使由 AI 理解，落到用户本地的文档仍会是中文（`INSTALL.md`、`AGENTS.md`、`skills/*/SKILL.md`、`commands/*.md`、`.cursor/commands/*.md`、`templates/*.md`）。
- `hooks/session-start` 会在会话启动时把 `skills/using-sandtable/SKILL.md` 注入上下文，说明 hook 行为与本地 skill 语言是一体的；若 English install 要求本地方法论文档是英文，则相关会话引导文本也要避免混语（`hooks/session-start`）。
- 当前安装红线已经成立且不能回退：存在即跳过、不覆盖用户已有文件；AGENTS 受保护追加；步骤 5 先看跳过清单；这意味着“换语言重装”不能靠覆盖已有文件来实现，只能如实报告未切换完成（`INSTALL.md`、`docs/sandtable/constraints.md`、`docs/sandtable/features/2026-06-02-easy-install/journal.md`）。
- 已确认的用户意图：
  - 语言跟随规则作用于“安装和放到用户本地的文档”。
  - 首期只支持中文与英文两种语言。
  - 语言不靠额外参数，由 AI 读取用户实际贴过去的话自行判断。
  - “放到用户本地的文档”**包含 `skills/`**，不只限于外层安装说明。〔来源：开发者答复，2026-06-06〕

## 3. 方案探索
- **方案 A：继续做“英文主文”全量替换。**
  - 优点：文档面统一。
  - 缺点：不满足“复制给 AI 的是什么语言，就安装什么语言”的新规则；中文用户本地也会被推向英文资产。
- **方案 B：给仓库补中英两套官方安装提示词，并让安装说明要求 AI 根据用户实际贴过去的话选择对应语言资产。**
  - 优点：直接贴合新规则；用户不需要额外参数；能保持安装入口统一。
  - 缺点：需要维护至少两套安装资产映射，并明确哪些文件是共享机器资产、哪些是随语言变化的自然语言资产。
- **方案 C：让 AI 自由翻译任意现有中文资产后再安装。**
  - 优点：表面上不用维护两套文档。
  - 缺点：违反“不猜测、不捏造”；无法保证命令边界、Red Flags、硬门禁等已调校文本不走样，也无法稳定复现。

**推荐：方案 B。** 它是唯一同时满足“语言跟随提示词”“中英双支持”“不靠 AI 临时翻译生成资产”的方案。

## 4. 用户故事 / 场景
- 作为一个中文用户，我希望把中文安装提示词发给 AI 后，安装到我项目里的 `AGENTS.md`、命令文档、skills、模板等仍然是中文。
- 作为一个英文用户，我希望把英文安装提示词发给 AI 后，安装到我项目里的同一套文档与方法论资产是英文，而不是混入中文。
- 作为一个使用 Codex 或 Kiro 的用户，我希望它们和 Cursor / Claude Code 一样都走同一条通用安装路径，而不是被文档暗示存在新的工具专属接线。
- 作为一个执行安装的 AI agent，我希望能仅凭用户贴过来的那句话判断该装中文还是英文资产，不需要用户再提供额外 flag。

## 5. 功能需求
- **FR1（官方中英安装提示词）**：`README.md` 与 `INSTALL.md` 必须提供两条官方可复制的安装提示词：中文版本与英文版本。两条都指向同一个 `INSTALL.md` 路径，但语句本身分别明确表达“按这句话的语言安装对应语言资产”。〔已确认：开发者答复“语言由 AI 读取用户实际贴过去的话自行判断”〕
- **FR2（按整条官方提示词正文选择语言）**：`INSTALL.md` 必须明确要求 AI 在执行安装前，只在**用户消息经空白归一化后恰好等于官方中文提示词正文或官方英文提示词正文**时自动选择语言：命中中文正文 → 安装中文资产；命中英文正文 → 安装英文资产；首期仅支持这两种。若用户消息包含任何额外包装文字、混合语言、两条提示词同时出现、或只是非官方改写版，则 AI 不得自行猜测，必须先澄清用户想要的安装语言。不得要求用户再提供独立语言 flag。〔已确认：开发者答复 + 红队收口〕
- **FR3（本地资产语言范围）**：被安装到用户项目中的自然语言资产必须随所选语言切换，至少覆盖：`AGENTS.md`、`CLAUDE.md`（若存在独立文本）、`.cursor/rules/sandtable.mdc`、`commands/*.md`、`.cursor/commands/*.md`、`skills/` 下所有安装后仍会被命令或 skill 引用的自然语言文件（含 `SKILL.md` 与各类 prompt 模板）、`templates/` 目录下的本地化模板、`scripts/sandtable-init.sh` 中的用户可见文本，以及 hook 相关自然语言包装或错误提示（包括 `hooks/session-start` 与 `hooks/run-hook.cmd` 的 wrapper 与 fallback 错误文本）。〔已确认：开发者明确要求“包含 skills/” + 主 agent 核读相关 prompt 模板〕
- **FR4（共享机器资产保持单份）**：纯机器接线文件若不承载自然语言语义，可继续共享单份，不因语言切换而复制，例如 `hooks.json` / `hooks-cursor.json` 之类机器配置；但如果某个共享文件包含面向用户或 AI 的自然语言文本，则它必须纳入 FR3 的语言切换范围。〔已确认：来自当前文件事实〕
- **FR5（Codex / Kiro 仍走通用安装路径）**：文档必须把 Codex 与 Kiro 明确纳入通用安装对象，但**不新增**它们各自的专属 rules / hooks / marketplace / 脚本接线。〔已确认：开发者答复〕
- **FR6（不覆盖现有文件，换语言时如实报告）**：语言选择不能突破现有安装红线。若目标项目里已存在对应文件或目录，安装必须继续“存在即跳过、记入跳过清单、核心项跳过即报告安装不完整”；因此用户后来改用另一种语言重新安装时，AI 只能如实报告哪些内容因不覆盖规则而未被切换，不能静默混语或强行覆盖。对于语言相关安装资产（`AGENTS`、rules、commands、Cursor commands、skills、templates、`scripts/sandtable-init.sh`、`hooks/run-hook.cmd`、`hooks/session-start`），安装必须先按**整个 locale pack**做预检：只要任一目标路径已存在，就不得继续复制任何该 locale 的语言相关资产，而是直接报告语言切换未完成并列出冲突路径；共享机器文件可继续独立按非覆盖规则处理。〔已确认：来自既有 INSTALL/constraints 红线 + 红队收口〕

## 6. 验收标准（成功定义 · 抽象层）
> §5 只写抽象成功定义；具体可演练场景下沉 `tests.md`。`tests.md` = 理解闸门，§5 = 完成闸门。
- [ ] 用户仅凭自己复制给 AI 的中文或英文安装提示词，就能让 AI 安装对应语言的本地 Sandtable 文档资产。
- [ ] 中文安装与英文安装都不会改变现有命令边界、安装护栏或方法论语义。
- [ ] Codex 与 Kiro 被明确支持，但仍只通过通用安装路径接入。
- [ ] 若项目已有同名文件导致无法切换语言，安装会诚实报告“不完整/未切换完成”，而不是覆盖或假装成功。

## 7. MUST（绝对要做）
- 必须保留现有统一默认路径：让 AI 读取 `INSTALL.md` 并安装到当前项目。
- 必须同时提供中文与英文两条官方可复制提示词。
- 必须让 AI 以用户消息里命中的**官方提示词正文**来判断中/英语言，不要求额外 flag。
- 必须让安装到用户本地的 `skills/` 与其它自然语言资产一起随语言切换，且包含被命令/skill 二次引用的 prompt 模板。
- 必须保持 `templates/` 仍是生成产物的唯一模板根目录；英文模板也必须位于 `templates/` 之下，而不是挪到第二个平行模板根。
- 必须把语言相关安装资产视为一个 locale pack 先做预检，不能在已发现旧语言冲突后继续部分复制新语言资产。
- 必须保持已有命令边界、安装护栏、异常语义和 Sandtable 术语关系不走样。

## 8. MUST NOT（绝对不能做）
- 不做未被要求的兜底逻辑 / 不节外生枝。
- 不新增 Codex / Kiro 专属插件、专属 rules 目录或新的安装脚本。
- 不靠 AI 运行时自由翻译现有中文资产来冒充英文安装。
- 不把带包装词、混合语言或非官方改写的用户消息擅自判成某个安装语言。
- 不把 README 默认路径改回 `Claude Code marketplace` / `Cursor` 分栏，也不夸大“所有 AI 都有原生插件市场安装”。
- 不为“切换语言”破坏既有不覆盖红线。

## 9. 非目标 / 暂不做（YAGNI）
- 不把 `docs/sandtable/features/` 下的历史 feature 文档全部翻成英文。
- 不支持除中文 / 英文以外的第三种语言。
- 不为 Codex / Kiro 设计新的运行时集成协议。
- 不要求已安装项目在不删除旧文件的前提下自动完成语言切换。
