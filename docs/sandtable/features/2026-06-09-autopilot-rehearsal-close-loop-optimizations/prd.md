# PRD · 自动模式、推演口径、live 完整性与 close loop 优化

## 1. 目标

让 Sandtable 的自动模式更像真正的“无人值守自主推进”，同时让推演与对抗回到“发现真实问题”的质量目标，并补上实现预演完成后的完整性核查，减少用户在 close loop 中已经做出选择后仍被要求复制命令的额外操作。

本需求直接服务 `project.md` 的北极星：把 Sandtable 方法论插件做成开发者真正愿意用的流程，而不是机械执行固定仪式。

## 2. 背景与现状

- 自动模式当前把最低配额写成硬门槛：mental 至少 3 轮、redteam 至少 3 轮、impl 至少 2 轮，见 `skills/autonomous-orchestration/SKILL.md` 与 `commands/sandtable-autopilot.md`。
- `skills/state-and-memory/SKILL.md`、`templates/state.md`、`templates/en/state.md` 也把默认 `autonomy.min_rounds` 固定为 `{ mental: 3, redteam: 3, impl: 2 }`，恢复时按 `completed_rounds < min_rounds` 判断下一步。
- 头脑推演和红蓝对抗当前强调“异常即停”和“可复现杀招”，但部分措辞容易把子 agent 推向“为了找问题而找问题”的行为。
- 实现预演当前要求完整实现、不留 TODO，并要求主 agent 不轻信 `DONE`、抽查 diff/测试/越界；但没有把“自认完成后用推演/红蓝对抗专门检查是否 100% 对照 PRD、tests、plan 实现”写成强流程。
- `closing-the-loop` 当前完整收尾固定包含“复制即用”区块；手动多分支必须 AskQuestion。缺口是：当用户已经通过 AskQuestion 或自然语言明确选择下一步时，agent 仍可能只输出一份可复制命令并停止。
- 历史教训：涉及语言相关资产时，必须按 `INSTALL.md` 的源路径映射同步中文根源、插件镜像、Cursor 命令镜像、英文 locale 与 `templates/en/`，不能只改最显眼的目录。

## 3. 方案探索

### 方案 A · 只改自动模式配额文本

把 3/3/2 改成 1/1/1，其他行为不变。

优点：改动最小。缺点：仍然把自动模式理解成固定配额闭包，只是配额变少；无法表达“至少一轮后自主判断是否继续”的核心意图。

### 方案 B · 改成“最低覆盖 + 自主追加”的自动编排

把硬配额改为三类推演至少各完成一轮；达到最低覆盖后，由主 agent 基于风险、复杂度、异常历史、实现差异、测试信心自主决定是否追加 mental/redteam/impl，且非阻塞时不得中断询问用户。`state.md` 仍记录 `min_rounds` 与 `completed_rounds`，但配额只代表最低覆盖，不代表必须机械跑满固定轮数。

优点：贴合“自动、自主、不打扰”的产品意图；保留可恢复状态与最低质量底线。缺点：需要同步修改多个技能、命令、模板和英文镜像。

### 方案 C · 引入风险分级策略

在方案 B 基础上建立更正式的风险分级表，例如低/中/高风险分别决定追加轮次和 agent 数。

优点：更可解释。缺点：本轮会显著扩大范围，并可能把流程再次做得机械化。

### 推荐

推荐方案 B。本轮只定义“最低覆盖 + 自主追加”的原则、决策依据和落盘要求，不引入完整风险分级框架；这样能解决当前痛点，同时保持外科手术式改动。

## 4. 用户故事 / 使用场景

- 作为开发者，我触发 `/sandtable-autopilot` 后，希望 AI 至少做过 mental、redteam、impl 各一轮，但之后由它自己判断是否需要追加，而不是被固定 3/3/2 轮次拖住。
- 作为开发者，我希望头脑推演和红蓝对抗发现真实、可复现、会影响目标的问题，而不是为了制造 anomaly 把边界想得很偏。
- 作为开发者，我希望 live 子 agent 说完成时，系统能专门检查它是否完整覆盖 PRD、tests 和 plan，避免只实现了其中一部分就进入复盘。
- 作为开发者，我在 close loop 里已经选择某个问题/路径后，希望 agent 直接按我的选择继续，而不是再给我一段命令让我复制。

## 5. 功能需求

- **FR1（自动模式最低覆盖）**：`/sandtable-autopilot` 的硬性最低要求改为 mental、redteam、impl 各至少 1 轮；每类至少有 1 个合格子 agent/候选完成该轮。〔来源：开发者需求 1；RECON〕
- **FR2（自动模式自主追加）**：完成最低覆盖后，主 agent 必须自主判断是否追加某类推演/对抗/实现预演。判断依据包括但不限于：需求复杂度、改动面、历史教训命中、异常/攻破是否刚修复、实现候选差异、测试信心、主 agent 抽查结果。非真实阻塞时不得为了“是否继续”打断用户。〔来源：开发者需求 1〕
- **FR3（状态语义更新）**：`state.md` 的 `autonomy.min_rounds` 默认值、模板与恢复说明必须表达“最低覆盖”而非“固定必须跑满多轮”。老 feature 中已有 3/3/2 历史状态不强制迁移。〔来源：RECON〕
- **FR4（头脑推演真实问题口径）**：头脑推演仍保持不猜测、异常即停，但文本和子 agent prompt 要明确：只有与 PRD/plan/code reality 冲突、逻辑无法闭环、影响范围超出预期、红线被违反、或关键事实无法确认且会影响决策时，才返回 `ANOMALY_FOUND`；不鼓励为了挑刺制造偏离实际的极端场景。〔来源：开发者需求 2〕
- **FR5（红蓝对抗真实攻破口径）**：红蓝对抗仍要求可复现杀招和主 agent 亲自核实，但要弱化“为了击溃而击溃”的表达，明确空泛风险、纯猜测、无现实触发路径、与本需求无关的脑洞不算 `BREACH_FOUND`。〔来源：开发者需求 2〕
- **FR6（live 完成后完整性检查）**：实现预演子 agent 自认 `DONE` 前后，必须逐项对照 `prd.md`、`tests.md`、`plan.md` 输出覆盖矩阵；主 agent 收到 `DONE` 后必须独立重算文档结构化核对基准，并对照候选 worktree 的真实 diff / 改动文件清单核对是否 100% 覆盖文档和计划，可根据复杂度亲自检查，或派只读 mental / redteam 风格子 agent 辅助审查。任何漏项、少报键、部分实现、未验证的验收标准、缺少真实 diff 证据、或与计划不一致的实现，都要转为 `ANOMALY_FOUND` / `BLOCKED`，不得进入 debrief。〔来源：开发者需求 4；TESTCASES 确认反馈〕
- **FR7（close loop 已选择即续跑）**：当用户已经通过 AskQuestion 选择了某条路径，或自然语言明确表达“按 X 继续/就选 X/确认 PRD 并继续”，agent 应在同一回合直接执行该选择对应的下一步；只有在命令边界确实要求停（如 `/sandtable-start` 写完 PRD 等待确认）或存在真实阻塞时，才输出完整收尾并停止。PRD 确认必须来自可追溯的开发者输入，并在继续前或同时写入 `state.md` 或 `journal.md`：AskQuestion 确认必须记录 answer id 或 `source: askquestion:<id>`，自然语言确认必须记录用户原话摘录、确认时间和用户消息来源；agent 自写 journal、`autonomy.last_decision`、`phase` 变化、仅写“AskQuestion 答复”或无来源的 state 字段不得伪装成开发者确认。〔来源：开发者需求 5；推演修正〕
- **FR8（close loop 模板降噪）**：完整收尾仍可保留推荐和模板，但不得在用户已选择路径后把“可复制命令”当作唯一动作。若已经执行了用户选择，收尾应报告执行结果和下一状态，而不是要求用户重复输入同一选择。〔来源：开发者需求 5〕
- **FR9（多镜像同步）**：所有被修改的中文根源资产必须同步到 `plugins/sandtable/...` 与 `.cursor/...` 对应镜像；英文资产必须同步到 `locales/en/...` 和 `templates/en/...` 的真实源路径。〔来源：`docs/sandtable/lessons.md` 与 `INSTALL.md`〕

## 6. 验收标准

- 自动模式文档、命令与状态模板不再把 3/3/2 当作不可降级硬门槛；默认最低覆盖为 mental/redteam/impl 各 1 轮。
- 自动模式达到最低覆盖后，文档要求主 agent自主追加或进入评估，并记录 `autonomy.last_decision` 的理由；非阻塞路径不询问用户“要不要继续”。
- 头脑推演与红蓝对抗的技能和 prompt 明确“真实问题/可复现攻破”口径，减少为了制造发现而偏题的表述。
- 实现预演 `DONE` 的返回格式和主 agent 编排要求包含 PRD/tests/plan 覆盖矩阵；主 agent 必须独立重算结构化核对基准并核对真实 diff / 改动文件清单，可亲自或按需派只读子 agent 辅助核查，缺少任何必做项、少报键或缺少真实改动证据时不得进入 debrief。
- close loop 对“用户已选择路径”的处理规则明确：直接续跑对应动作，执行后再收尾；不再仅输出复制命令并停止。
- PRD 确认边界有可核实证据要求，并且必须在继续前或同时持久化到 `state.md` 或 `journal.md`；AskQuestion 确认必须带 answer id 或 `source: askquestion:<id>`，自然语言确认必须带用户原话摘录、确认时间和用户消息来源；无开发者来源、仅写“AskQuestion 答复”或只有时间戳的 journal/state 记录不得绕过确认点。
- 中文根源、插件镜像、Cursor 命令镜像、英文 locale 与模板源路径保持一致；不出现只改一处的语言资产漂移。

## 7. MUST

- 必须保留三类推演至少各一轮的质量底线。
- 必须保留异常/攻破/阻塞后主 agent 亲自核实、回写文档、重演的闭环。
- 必须保留自动模式“非真实阻塞不打扰用户”的纪律。
- 必须把实现预演的“完整性覆盖检查”写进子 agent prompt、主 agent skill 和相关 slash 命令；主 agent 必须独立重算结构化核对基准并核对真实 diff / 改动文件清单，检查方式由主 agent 依据复杂度决定，可亲自核对或派只读子 agent 辅助。
- 必须同步中文根源、插件镜像、Cursor 命令镜像、英文 locale 与模板源路径。
- 必须确保 PRD 确认记录可追溯到开发者输入，并在继续前或同时持久化到 `state.md` 或 `journal.md`；AskQuestion 确认必须带 answer id 或 `source: askquestion:<id>`，自然语言确认必须带用户原话摘录、确认时间和用户消息来源；agent 不得伪造用户原话、自写“AskQuestion 答复”或自行设置确认字段来绕过 PRD 确认门禁。

## 8. MUST NOT

- 不得把“至少一轮”实现成“只跑一轮就永远停止”；达到最低覆盖后仍要由主 agent 根据风险自主判断。
- 不得删除 Sandtable 的异常即停、红线核查、可复现证据和不猜测原则。
- 不得为了减少打扰而吞掉真实阻塞；需要用户提供产品意图、权限、登录、外部资源时仍必须停下来问。
- 不得引入新的第三方依赖或脚本运行时。
- 不得改动与本需求无关的安装、脚手架、FEEDBACK/bugfix 语义。

## 9. 非目标 / 暂不做

- 不做完整风险分级框架或评分模型。
- 不迁移历史 feature 的既有 `state.md` 配额记录。
- 不改变 `/sandtable-start` 写完 PRD 后必须等待开发者确认的命令边界。
- 不改造 AskQuestion 工具本身。
